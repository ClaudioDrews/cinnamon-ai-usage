# Contract v1

Collector: `python3 backend/collector.py collect [--force]`; prints only UTF-8 JSON. Without arguments it uses collect. `read` returns the cache without network; `demo` returns synthetic data WITHOUT writing the cache. `worker ID` queries a single provider; `diag ID` returns, for the services that declare it, the structure of the response as field names, types and number ranges — never values or credentials. Window: `python3 backend/window.py [--demo]`. Everything works in the source tree and installed: backend/ alongside applet/ in the source; installed, backend/ stays inside the applet directory. The applet locates backend/ inside metadata.path; installation copies it.

Non-secret configuration: ~/.config/cinnamon-ai-usage/config.json. Private cache: ~/.cache/cinnamon-ai-usage/snapshot.json. Default TTL 120 seconds. IDs: codex, claude, antigravity, grok, nous, opencode, deepseek, openrouter, meta.

Example output (no secret):
```json
{"schema_version":1,"generated_at":"2026-09-25T20:00:00Z","services":[{"id":"codex","label":"Codex","status":"ok","message":"","source":"codex app-server","read_at":"2026-09-25T20:00:00Z","last_used_at":null,"recency_basis":"unknown","metrics":[{"id":"primary","label":"Janela de 5 h","kind":"quota","used_percent":42.0,"value":null,"currency":null,"window_seconds":18000,"reset_at":"2026-09-25T22:00:00Z"}]}]}
```

Status: ok, stale (previous data preserved), unavailable (source absent/service closed), unconfigured (credential absent), error, disabled. When `stale`, the `stale_reason` field states the real reason: `pending` (the refresh interval has passed and there has been no new reading) or `failure` (the most recent refresh failed); old snapshots may not carry the field, and then the message identifier decides.

Translatable text is data with an identifier, and the identifier is what the interface displays: `message_id` + `message_args` on the service and `label_id` + `label_args` on the metric carry the msgid (English) and the placeholder values, while `message` and `label` keep the text translated into the collection language, for whoever consumes without a catalog. The presenter resolves the identifier in the current language and only uses the saved text when the identifier is absent, is unknown to the catalog or there is no catalog at all (English). The fields are optional and additive in `schema_version` 1: an old snapshot without them stays valid and shows the saved text. The saved identifier is always a uniquely-formed entry in the catalog: the persisted record does not keep the number that the plural selection would require, so a sentence with a count uses the singular with the number as a placeholder (`{hours} h window`), and a plural entry does not qualify as an identifier. A placeholder takes a **raw** value, in one of three shapes: text (data from the service, or text an older collection saved there), number, and part list. A number is written at presentation time, in the language in force (`i18n.arg_text()`, `_argValue()` in the panel) — an integer with no decimal place, a fraction with one — so an already formatted number never goes into a label msgid: one record collected in Portuguese says `Janela de 1,5 h` and the same record in English says `Window of 1.5 h`. Multi-clause text (the note of the service) travels as a list of parts, each part `{"id": msgid, "args": {...}, "text": <text in the collection language>}`, joined at presentation time with the space that separates the block from the sentence; an empty list leaves no leftover space, and a part whose identifier the catalog does not know falls back to its saved text and then to the msgid. The origin of a reading follows the same rule: `source_id` + `source_args` next to `source`. A technical identifier is never built from a label — the label is text and follows the language: the id of an Antigravity quota with no model name comes from the raw data of the reading (the model id in the response) or, with no name at all, from the position of the model in the answer, and `id_aliases` carries the ids an earlier version wrote from the translated label so the history already on disk stays comparable. Changing the language does not discard a reading, does not force collection and does not mark anything as stale. An absent percentage is null, never zero. kind: quota, balance, spend. value in a monetary unit with currency; only quota has used_percent. Several metrics per service may exist. source, message are sanitized public texts, never a raw response or a network exception.

last_used_at is NOT read_at. It is only filled when consumption increases or balance decreases between comparable readings; recency_basis=observed_change, an approximation. In the future effective usage timestamps may use reported. The first reading has unknown recency. The cache preserves recency. Without history, do not invent: the menu shows up to five lines, first those with observed use and then those with the most recent reading, marking on each line when there is no observed use; a service without a reading does not enter the menu. Sort descending; do not reorder while the menu is open. Include the last stale value with a warning if a recent service fails.

Applet: IconApplet with a symbolic icon (SVG with transparent background), without border; the alert color goes on the icon itself — yellow from 70% used and red from 90%, by the highest valid quota, ignoring stale readings and metrics without a percentage; with no alert the icon returns to the theme color. The applet does not trust `status` alone: an `ok` reading older than the configured interval (plus a minute of slack, so the next cycle arrives without flickering) counts as stale, and a 60 s loop re-evaluates that age without querying any service — that is what keeps the state correct when collection is paused. A single click opens a menu with up to five lines: first those with observed use, then those with the most recent reading; a service without a reading does not take a line (it appears in the tooltip and in the window). A double click on the icon opens the window (use a short delay based on the system double-click-time to distinguish safely; cancel the timeout on removal). The menu also has See all services…, Update, Credentials…, native Settings… when available. Snapshot loaded asynchronously via Gio.Subprocess.communicate_utf8_async, watchdog and cleanup. No shell spawn, no synchronous network, no access to a secret in the applet. Start collect when it loads and at every TTL. Force only on request. Show an error indicator separately from quota: in the menu and in the tooltip, naming the services with status `error` ("Reading failed: {services}") and those with `stale` ("Stale reading: {services}"), without changing the quota color. Bar by St/CSS composition.

GTK3 window: Gtk.Application id claudio.drews.CinnamonAIUsage, single instance; scrollable window with every configured/queryable service and the states of the others, preferably separating 'No reading' into an expander. Shows all metrics, reset, last update, source, approximate recency. Update runs the collector asynchronously; do not block GTK. For demo, a fixture of the demo subcommand clearly marked. Do not access credentials. Global collection timeout 50s; UI watchdog 60s. Locale pt-BR. System theme.

## Credentials

Order, always without a shell: (1) the **system keyring** (Secret Service), where the window `credentials_window.py` writes what the person types — it applies to any of the accepted names of the credential, and beats file and environment; the window always writes the preferred name; (2) a `NAME=VALUE` file at the path of `config.json:credentials_path`; (3) environment variables. Services that authenticate by login use `token_files` (JSON; the first `access_token` at any level). The program knows no fixed credential path of any machine. No value is printed, logged, displayed back or written to the cache; `config.json` keeps only paths, in mode 0600. Without a value, the service stays `unconfigured`.

The credentials window is a separate process, shows where each value would come from, clears the field after saving and offers removal from the keyring. The usage window does not read a secret: it only opens the credentials one.

## Meta AI (Muse Code)

The `meta` id reads the subscription of the Muse Code application — current window (`window`, with `window_duration_mins`) and `weekly` —, not the API usage billing. The only source is `POST https://api.meta.ai/muse-code/key`, the same call the client makes on startup: it issues a credential, but it is idempotent (verified on 26/09/2026: it returns the same `api_key` and the client's `auth.json` stays intact). The token comes from the Muse Code login itself, in the order the client uses: `token_files.meta` in the configuration, `$MUSE_AUTH_PATH`, `$XDG_CONFIG_HOME/muse/auth.json` and `~/.config/muse/auth.json`; the file is read by the first `access_token` at any level of the JSON. Without a token the service stays `unconfigured` and no call is made. The connector does not execute the Muse Code binary.

As there is no documentation of a usage limit, the connector imposes a minimum interval of its own: `meta.min_interval_seconds`, default 900 s, accepting from 300 s to 24 h. The interval counts the last **attempt**, not only the last good reading: after a failure (HTTP 429, for example) the next query waits the interval instead of repeating the call — with no reading to reuse, the return is `unavailable` with "Consultation deferred: …". The private cache keeps the stamp of the attempt and its outcome (`attempt_status`, `attempt_message`) next to the last good reading: when there is a previous reading, the reused one keeps naming the failure (`stale_reason` `failure` and the message of that attempt) until the service answers again — reusing does not erase what happened. Inside the interval there is no new call: the previous reading is reused from the private cache `~/.cache/cinnamon-ai-usage/meta.json` (0600, only the account digest, never the token) and keeps the real `read_at`, so that the service appears as a stale reading when the TTL passes. A network failure or a response without a percentage does not become zero: the service stays `error`/`unavailable` and the previous value is preserved. When the response arrives without the percentages, the message suggests `diag meta` — and that diagnostic exists: the query is the same route as the collection, and the report brings field names, types and range of the numbers, besides telling, field by field, which of the expected paths (`subs_usage.window.used_percent`, `subs_usage.weekly.used_percent`) are absent, null or of another type. No values, account identifiers or paths of the machine; without a credential, the diagnostic makes no call at all. A test reads the messages of the module and the `DIAGNOSTICS` table so that no suggestion of `diag` points to a service without a report.

The percentage is an integer and Meta warns that it can go above 100: the bar goes up to 100 and the service note informs the reported number. There is no spend metric in dollars for this service — the models API publishes no price, and a token count without a price does not fit in this contract.

## Claude Code

The `claude` id reads the windows of the Claude Code subscription through the reading route `GET https://api.anthropic.com/api/oauth/usage`, with the login token and `anthropic-beta: oauth-2025-04-20` — the same route the CLI itself uses at `/usage`. No inference: the connector does **not** use `/v1/messages` nor any request that consumes the displayed quota, and never renews a credential. The token expires in about an hour and whoever renews it is the CLI; expired, the service stays `unconfigured` with the warning to run `claude` again.

The login is looked up in `token_files.claude`, then `$CLAUDE_CONFIG_DIR/.credentials.json` and finally `~/.claude/.credentials.json` (in that order; the macOS Keychain is not read). One `accessToken` at any level of the JSON is enough. Without a token, no call is made.

The percentage is used as reported, on the 0–100 scale, without the heuristic of multiplying a small value by 100. `five_hour` and `kind: session` become "5 h window"; `seven_day` and `weekly_all` become "Week"; `weekly_scoped` becomes "Week · {model}". An unknown type is ignored and a response without any recognized window stays `unavailable`, with the suggestion to run `diag claude` — never zero.

Its own minimum interval, `claude.min_interval_seconds`, default 300 s (from 120 s to 24 h), with the private cache `~/.cache/cinnamon-ai-usage/claude.json` (0600, only the account digest, never the token) and a real `read_at`: inside the interval the reading appears as stale by its own timestamp. As in the Meta connector, the interval counts the last attempt — a failure is not a reason to query again before time, and the recorded outcome (`attempt_status`) keeps the reused reading marked as a failure until the service answers.

Declared verification: implemented and covered by offline tests against the format documented by the community, **without verification on a real account**, as there is no Anthropic account on the author's machine. The route is declared by the community, not by Anthropic, and can change; when it changes, the result is unavailability, not an invented number.

## Implementation details

Dates: `read_at`, `generated_at`, `last_used_at` and `reset_at` always come out in ISO-8601 UTC with `Z`. The source can send epoch in seconds or milliseconds, or ISO-8601 with or without a timezone — ISO without a timezone is read as UTC, by declared convention (never discarded in silence).

`collect --ttl N` allows the applet to pass its interval (30–3600 s). `worker ID` is an internal command, limited to 30 s, executed in parallel by the collector. If a collection is already running, `collect` does not wait and does not force: it returns the last readings with the public field `notice` ("Refresh skipped: a collection is already running; the values are the last reading."). It is a warning, not an error — no service becomes a failure because of it, and the `notice` is of the moment, never written to the snapshot. `collect` applies to the output the same age evaluation as `read`: a reading `ok` older than the TTL comes out as `stale` with `stale_reason: pending`, and the real value stays in the metric; the cache keeps the raw state (status `ok` with the origin `read_at`), so that the verdict does not depend on the execution path. The private snapshot has `_identity` (digest of the identity of the account/key) to restart the comparison when the account changes; `collect/read` remove that field before printing. `demo` never uses cache or credentials.

A quota query only produces recency when the percentage increases in the same window/reset. Balances only produce approximate recency when they decrease; spend values when they increase. There is no claim of an exact time nor attribution to an agent. The UI does not change the ordering while the menu is open; reopening applies the new reading. Credentials are read only by the workers of their respective providers.
