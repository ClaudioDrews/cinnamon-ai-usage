# Language and translation

How the applet, the GTK windows and the collector are localized, and the vocabulary
to keep when a new string appears. Verified on Cinnamon 6.6.9 (26/09/2026).

## The rule this document exists for

Text a person reads is never hardcoded. It is written in English as a `msgid` and
translated in a catalog. The original mistake was the other way round — Portuguese
literals spread over every layer — and it turned a small applet into a translation
project: strings in provider messages, metric labels inside the JSON contract, date
and decimal separators fixed in code, and tests asserting Portuguese text. Adding the
infrastructure first is what makes the second language cheap.

## Mechanism

The gettext domain is the applet UUID, `ai-usage@claudio.drews`. Cinnamon itself
wires it for the **settings surfaces**, not for the panel:

- `js/ui/appletManager.js` binds the xlet domain to `~/.local/share/locale` before
  loading `applet.js`. That binding is what the shell's own translations use; the
  panel does **not** call `imports.gettext.dgettext`, because that resolves the
  language from the process locale and the shell is a shared process — a per-instance
  language preference would either do nothing to the text or change the locale of
  every other applet. The panel reads the `.mo` itself, per instance
  (`parseMo`/`catalogFor` in `applet/applet.js`), and the resolved language drives
  both the text and the number formatting.
- `cinnamon-settings/bin/ExtensionCore.py` and `xlet-settings.py` translate the
  **name and description from `metadata.json`** and the **descriptions, tooltips,
  units and combobox option labels from `settings-schema.json`** through the same
  domain, following the session language. That is why those JSON files hold English
  source strings and still appear in Portuguese. Consequence to keep in mind: the
  applet list and the preferences dialog follow the **session** language even when
  the panel is pinned to another one — the preference governs the panel.
- The Python side (`backend/i18n.py`) loads the same compiled catalog with
  `gettext`, searching `<applet>/locale`, then `~/.local/share/locale`, then
  `/usr/share/locale`. `<applet>/locale` is what makes a source checkout work
  without installing anything.

### Which language wins

Both runtimes resolve through the same rule — the GNU gettext one, which is also
what GLib does for the shell and what Python's `gettext` module does:

1. `LANGUAGE`, when set and not blank, **alone**: it is a list separated by `:`, and
   the other three variables are ignored. The first entry with a catalog wins.
2. Otherwise the first of `LC_ALL`, `LC_MESSAGES`, `LANG` that is set.
3. A tag is normalised (`pt_PT.UTF-8@euro` → `pt_BR`, `C`/`POSIX` → `en`), and a
   language only takes effect if its catalog exists. Nothing usable means English.

The panel and the backend have to agree here: before this rule, the backend merged
all four variables while `GLib.get_language_names()` (used by the panel) stopped at
`LANGUAGE`, so `LANGUAGE=fr_FR LC_ALL=pt_BR.UTF-8` showed English in the panel and
Portuguese in the window. `tests/test_i18n.py` and `tests/test_applet.js` run the
same mixed environments with the same expected answers.

Explicit preference is a separate axis: `language=auto` follows the session rule
above, and any other value wins over it — but if that language has no catalog the
result is English, never the session language.

```
locale/pt_BR.po                                  translations (hand-edited)
locale/ai-usage@claudio.drews.pot                template, generated
locale/pt_BR/LC_MESSAGES/ai-usage@claudio.drews.mo   compiled, versioned on purpose
scripts/i18n.sh                                  extract -> msgmerge -> msgfmt
scripts/xlet_strings.py                          the two JSON files, for xgettext
```

`install.py` copies `locale/` into the applet directory (Python backend) **and**
each `.mo` into `~/.local/share/locale/<lang>/LC_MESSAGES/` — the second copy is the
one the Cinnamon shell reads, and nothing installs an applet without it.

The `.mo` is committed: whoever installs from a git clone has no `xgettext`/`msgfmt`,
and the shell reads `.mo`, not `.po`.

## Writing code

- Wrap user-visible text in `_("English source text.")` — English, since a missing
  catalog must degrade to English, never to a language no catalog covers.
- Placeholders use `{name}`, filled by `i18n._f(text, ...)` in Python and `_f(text,
  {...})` in JS. Numbers, money and dates go through the language table before they
  reach the placeholder: `i18n.percent(42)`, `i18n.money(7.02, "USD")`,
  `i18n.datetime_text(moment)`, and `formatPercent/formatMoney/formatTime` in the
  applet. Never `f"{v:.1f}".replace(".", ",")`, never `strftime("%b")`, never
  `toLocaleTimeString("pt-BR")`: the process inherits the session locale, so a month
  name can come out in the wrong language and a decimal separator can come out in
  the wrong convention. `backend/i18n.LANGUAGES` holds the decimal separator, the
  date format and the money order per language, mirrored in `applet/applet.js`.
- A language only takes effect if its catalog exists, and an explicit request that
  cannot be honoured falls back to English — not to the ambient language. `auto`
  follows the session; any other value wins over the environment: who pins `fr` with
  no French catalog reads English, not the language of whoever was logged in.
- The language comes from the environment in the gettext order — `LANGUAGE` alone
  when set, otherwise the first of `LC_ALL`, `LC_MESSAGES`, `LANG` (see "Which
  language wins"). The applet setting `language` (`auto` by default) overrides it
  and, when fixed, is exported as `LANGUAGE` to every child process, so the
  collection, the usage window and the credentials window speak the same language as
  the panel.
- The panel does **not** use `Gettext.dgettext`: the shell process is shared, and
  switching its locale to honour one instance's setting would change the rest of the
  panel. `applet.js` reads the `.mo` itself (searching the applet directory, then
  `~/.local/share/locale`, then `/usr/share/locale`) and keeps one table per language;
  the resolved language governs both the text and the formatting of that instance.
  `cinnamon-settings` still translates `metadata.json` and `settings-schema.json`
  through the shell's domain, so the applets list and the settings dialog follow the
  **session** language: the setting governs the panel, not those two screens.
- Tests assert behaviour, not translation. When a test needs the text, it calls
  `_()` for the same msgid (`self.assertEqual(label, i18n._("Balance"))`) so the
  suite passes in any language; `tests/test_i18n.py` is the one place that checks the
  catalog itself, and it fails when a new msgid has no translation.
- `catch (_)` shadows the gettext function `_` in JS. Name the catch parameter
  `error` — inside a `catch (_)` block, `_("text")` is a `TypeError` waiting to
  happen.
- In GJS, `ByteArray.toString(slice)` stops at the first NUL byte: a plural entry is
  `"singular\0plural"`, so decoding the slice in one go silently drops the plural.
  Split the bytes on `0x00` and decode each segment (`parseMo` in `applet.js`).
- `GLib.file_get_contents` **throws** on a missing file in GJS instead of returning
  `[false, null]`. Check with `GLib.file_test` first and keep the read inside a
  `try`, or the applet dies during construction when a catalog is not installed.

## Texts that stay in the cache

`message` and `label` are written to the snapshot — and the snapshot outlives a
language change (TTL, readings reused inside the minimum interval, history preserved
after a failure, collection paused). Showing the saved text would show yesterday's
language; forcing a collection does not fix offline, a paused collection or a failure.

The rule: **the identifier is what gets displayed; the text is a fallback.**

- A record with translatable text carries the msgid next to it: `message_id` +
  `message_args` for a service, `label_id` + `label_args` for a metric. The `message`
  and `label` fields keep the text translated into the *collection* language, for
  consumers that have no catalog at all.
- Producers write the msgid through `N_()` — the gettext marker for "this is a
  msgid, do not translate it now". The emission API takes it (`service(...,
  message_id=...)`, `metric(..., label_id=...)`) and `Unavailable(message, status,
  args)` makes the exception's message the msgid, so the single error path in
  `collect_provider` gives all raise sites their identifier.
- Presentation resolves the identifier in the current language and falls back to the
  saved text when the identifier is absent (old snapshot), absent **from that
  catalog** (new connector), or the language has no catalog at all (English, where
  the msgid is the text). See `i18n.record_text()` and `_recordText()` in the applet.
  Presence is checked against the catalog itself, not by comparing the translation
  with the msgid: `{hours} h` and language names are legitimately identical to their
  source, and the comparison would treat them as missing — showing the saved text
  where the identifier plus its fresh arguments were right. A **plural** entry does
  not qualify as an identifier either (choosing the form needs the number, which a
  saved record does not carry): there the saved text is the correct answer, and both
  runtimes decide the same way.
- Arguments carry **raw** values. A number already formatted by the collection stays
  in the collection's convention, so a formatted number must not go into a label
  msgid: the presenter formats it (`formatPercent`, `i18n.percent`).
- A language change never costs a reading: nothing is discarded, re-collected or
  marked stale because of it. The private per-provider caches store the identifier
  too (`attempt_message_id`), for the same reason.

## Adding or changing a string

1. Write the string in English in the code, wrapped in `_()`.
2. `scripts/i18n.sh` — extracts msgids, merges into `locale/pt_BR.po`, compiles the
   `.mo`. New entries arrive empty and show up as untranslated.
3. Translate them in `locale/pt_BR.po` and run the script again.
4. `python3 -m unittest discover -s tests` and `node tests/test_applet.js`.

Never edit the msgid to fix a translation: a changed msgid is a new message, the old
translation is dropped as obsolete and the text disappears from the applet. Also
never leave an obsolete entry behind expecting it to work: `msgfmt` does not compile
obsolete entries into the `.mo`.

Every helper that carries a msgid has to be a `--keyword` of `xgettext` (`_`, `_t`,
`_n`, `N_`). When one is missing, extraction stops seeing those calls, `msgmerge`
retires the entries as `#~`, the `.mo` loses them and the interface silently falls
back to English — with a green build. `tests/test_i18n.py` refuses a catalog with
obsolete entries for exactly that reason, and its coverage list is built with `ast`
(not a regex) so implicit concatenation, `N_()` and `message_id=`/`label_id=` are all
seen: a regex once matched `__t(` and missed `_t(`.

`tests/test_i18n.py` also refuses, in the same file:

- an entry marked `fuzzy` — `msgfmt` leaves it out of the `.mo`;
- a plural entry whose forms do not match `nplurals` from the header, or a panel rule
  that disagrees with the header expression — pt_BR declares `plural=(n > 1)`, so zero
  is singular there and plural in English, and a generic `n === 1` would say "0 dias";
- a `.mo` that disagrees with the `.po` (fuzzy, truncated plural, stale catalog);
- a translation that loses or invents a `{placeholder}`;
- Portuguese prose outside the catalog: `PENDING_PROSE` counts those literals per
  file, so a new string without a translation fails in the commit that adds it, and
  the count only goes down as Fase 2 translates each module.

## Vocabulary (pt-BR ← → English)

Keep one term per concept; the catalog is only consistent if the source strings are.

```
coleta            collection        leitura             reading
coletar           collect           leitura antiga      stale reading
intervalo         interval          sem leitura         no reading
uso               usage             última coleta       last collection
uso estimado      estimated usage   recência            recency
cota              quota             atualizar           update
janela            window            adiada              delayed
semana            week              indisponível        unavailable
saldo             balance           não configurado     not configured
gasto             spend             sem uso observado   no observed use
recarga /
crédito pré-pago  prepaid credit    balão (dica)        tooltip
percentual        percentage        painel              panel
serviço           service           credenciais         credentials
provedor          provider          cofre do sistema    system keyring
conector          connector         preferências        settings
```

Do not translate: service names (`Codex`, `Grok`, `OpenRouter`, `Muse Code`), model
names, field names of the JSON contract, command names (`collect`, `read`, `diag`),
or file paths.
